Fact-check, diff de impacto para PRs y verificación por cobertura en Waymark

Waymark tiene tres formas de comprobar que un mapa sigue siendo fiel al código. La primera es un fact-check hecho por un agente escéptico: arranca con `waymark check` [1a] o con la tool `waymark_check` [1g] y sus veredictos se sellan con huellas en `recordCheck` [2c]. La segunda es un diff de impacto: `diffMaps` [3a] cruza las líneas de `git diff` con el bloque de cada nodo, `renderDiff` [4a] arma el reporte y una GitHub Action lo publica como comentario en el PR [4m]. La tercera es la verificación por ejecución, que pasa la cobertura V8/lcov a marcas hit/miss por nodo [5g] [5h].

Visor HTML de Waymark: render y sincronización de panel, código y diagrama

El servidor guarda cada mapa y genera un HTML autocontenido [1a] que incrusta una instantánea de los archivos referenciados [1c] junto con el documento, el estado de verificación por nodo, el markdown y el Mermaid [1e]. En el navegador, `viewer.client.js` reconstruye un modelo indexado [2a, 2c] y pinta tres superficies — panel del mapa [3a], vista de código [4a] y diagrama SVG [5a] — que quedan sincronizadas por una única función `select` [6a].
